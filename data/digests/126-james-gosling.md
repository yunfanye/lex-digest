# One-liner

James Gosling recounts the creation of Java and a lifetime of programming-language work, explaining how portability, virtual machines, garbage collection, tooling, and compatibility shaped a language meant for software that had to survive changing hardware.

# Summary

The virtual machine and bytecode boundary let applications target a stable execution model while processors and operating systems changed underneath them. Garbage collection removed a large class of manual lifetime errors, while introducing runtime and latency questions that the VM had to solve well enough for production systems.

A widely deployed language cannot casually repair every early design mistake because old binaries, libraries, tools, and user expectations become part of the platform contract. Gosling's story includes compilers, debuggers, libraries, runtime systems, and developer culture, showing why syntax alone rarely explains whether a language lasts.
